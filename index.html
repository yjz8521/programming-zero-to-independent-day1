DAY 1 / CONCEPT

今天不追求寫很多 Code，先建立正確的觀察方式。

程式設計是把模糊的目標，拆成電腦能照順序執行、而且可以驗證的指令。今天你會先練習「說清楚、預測、再確認」。

今天的證據

你不需要證明自己很快。你要留下的是：

  • 一個自己的分類理由
  • 一次先預測再檢查
  • 一個還不懂、但已經說清楚的問題

01 · CORE VOCABULARY

先把「東西的角色」說清楚

今天先不用背正式定義。先用生活中的比喻建立方向，再用小題目確認你是否真的分得出來。

Program程式

一組為了完成任務而安排好的指令。像是一份可以照做的工作流程。

不是單一行 code；Program 可以由很多段 code 組成。
File檔案

一份有名稱、可以保存內容的資料。day01.md 就是一個 file。

不是 folder；file 裡面放內容，folder 用來整理東西。
Terminal終端機

讓你用文字輸入指令、看見回覆的介面。

Terminal 是介面；Shell 是解讀指令的程式。
A
快速分類

day01.md 最接近哪一個？

先選一個，再說服自己：你是根據「它保存了什麼」還是「它在哪裡」來分類？

02 · PRACTICE LAB

把想法變成可以檢查的答案

程式設計的可靠感，不是來自猜對，而是來自「我知道我怎麼驗證」。下面三個小題會留下你的推理痕跡。

B
步驟排序

把「找到 Day 1 教材」排成可執行順序

每個位置選一個步驟。不要用「我平常會這樣做」帶過，想像另一個完全不知道資料夾位置的人。

C
Output Prediction

不執行，先寫出你預期的畫面

print("Python")
print()
# 這一行不產生 output
print("Zero to Independent")

正確 output 
Python

Zero to Independent

注意：# 這一行不產生 output 是 comment，不會出現在畫面；中間的空白行來自 print()。

小提醒如果你需要按很多次「檢查」，那不是失敗；請觀察每次回饋，記下你改變了什麼。
